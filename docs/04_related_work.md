## M. Methods：方法分類（由舊到新、由簡到繁）

### M-1 AI Technology

**(1) 工具型推理 Agent（2022–2023）**
ReAct 讓語言模型交替進行任務推理、外部動作與觀察，在問答、查證與互動環境中證明了取得外部事實的價值。但作者也觀察到重複動作與無效檢索造成的失敗 [A1]。這是本專題「受限規劃＋工具呼叫」的方法源頭；同時也提醒我們，Agent 需要預算與停止條件。

**(2) LLM 直接理解時序（2024–2025）**
Zhou 與 Yu（ICLR 2025）系統性地檢驗 LLM 能否理解時序異常。他們發現：影像輸入優於文字輸入；要求明確推理並不能改善表現；而且沒有證據顯示 LLM 能理解細微的真實異常 [A6]。這是本專題「**LLM 不判讀數值**」的最直接證據。

**(3) LLM 作為「可檢查中介」的產生器（2025）**
- Argos 讓 LLM 產生可執行的 Python 異常規則，經修復與審查後與既有偵測器融合。偵測階段不再呼叫 LLM，以換取可重現性 [A2]。
- Yang 等人讓多模態 LLM 複核傳統偵測器提出的候選異常。結果呈現「誤報降低」與「真異常保留」之間的取捨 [A3]。
- Time-RA（ACL 2026 Findings）把異常偵測擴展為「分類＋文字說明」，建立 RATs40K 並以 LoRA 微調。但說明是 AI 輔助標註，不等於物理因果 [A5]。

**(4) 建築／能源領域的 LLM Agent（2025–2026）**
- Mulayim 等人以 GPT-4o 透過 Brick 語意模型查詢 BAS 資料並生成 Python 分析。三個問題各測五次，其中氣流下降題只成功 3/5，也出現遺漏感測器的情形 [A4]。
- He 與 Jazizadeh 的情境感知能源管理 Agent 以 120 個查詢、4 個住宅資料集評估：裝置控制正確率 86%，能源分析 77%，成本估算僅 49% [A7]。
- 2026 年的回顧編碼了 66 篇 HVAC LLM 研究，只有 4 篇達到試點層級證據，沒有任何一篇回報持續部署。作者認為 LLM 較適合作為語意與工作流程層，而不是自主控制器 [A10]。

**(5) 時序基礎模型與領域微調（2025）**
- Mulayim 等人評估時序基礎模型（TSFM）於建築能源管理任務：在未見資料上僅略優於統計模型，加入共變量也不一定有幫助 [A8]。
- 在 HVAC 故障診斷上，以標註資料微調的領域 LLM 明顯優於通用模型 [A9]。但這需要設備層級的故障標籤，而建築總表資料沒有。

### M-2 Domain Know-how

**(1) 宏觀需求與政策脈絡（2026）**
- 建築占 2025 年全球用電增量近 45% [D1]，並預計占 2025–2030 年新增需求 49% [D2]。
- 建築用能約占全球用電的一半 [D14]。
- 臺灣服務業與住宅部門合計約占全國用電 36.6%（2025，自行加總官方資料）[D15]。

**(2) 量測與驗證（M&V）基準（2016–2023）**
- DOE FEMP 定義了 M&V Option A–D，並明言整棟建築的 Option C 無法驗證個別措施 [D8]。
- Granderson 等人以 537 棟建築測試 10 種以區間資料建立的自動化基準模型，12 個月訓練資料下的中位數 CV(RMSE) 皆低於 25% [D11]。

這兩份文獻共同支持：統計基準可以做到可靠，但「偏離量 ≠ 節電量」「總表 ≠ 設備根因」。

**(3) 公開資料集與資料品質（2020–2022）**
- BDG2 提供 1,636 棟非住宅建築、3,053 個計量表的兩年逐時資料 [D3]。維護者另提供 cleaned 版本，會移除 S-H-ESD 離群值、超過 24 小時的連續零值與電表絕對零值 [D6]。
- LEAD1.0 以同源的 ASHRAE GEPIII 資料人工標註 1,413 條電表時序的異常，並評測 8 種方法 [D10]。LEAD 的做法是保留並標註異常，而不是刪除。

**(4) 建築能源分析的實務流程（2020–2023）**
- LBNL Smart Energy Analytics Campaign：104 個組織、約 6,500 棟建築，EIS 與 FDD 使用者年節能中位數分別為 3% 與 9% [D7]。
- 資料驅動 FDD 的回顧把流程整理為資料蒐集、清理、前處理、基準、偵測、診斷，並指出真實建築部署、標竿比較、可擴展性與可解釋性仍是挑戰 [D12]。

**(5) 電表異常偵測與預測模型（2025–2026）**
- Orvati Nia 等人（IEEE TPEC 2026）在 LEAD 的 406 棟建築上，以統一的前處理與門檻比較 GAN-LSTM 與 6 個 baseline，GAN-LSTM 的 F1 為 0.89 [D13]。
- Park 等人以 Chronos 在日本 SUSTIE 商業建築上比較零樣本、全量微調與 LoRA，顯示本地調整與上下文長度會影響預測品質 [D9]。

## N. New proposed：新趨勢與本專題定位

**新趨勢：**
1. LLM 從「直接回答」轉向「產生可檢查的中介物」：規則 [A2]、程式 [A4]、工具紀錄與證據。
2. 能源領域開始出現 Agent 原型 [A4][A7]，但部署證據極少 [A10]。
3. 時序基礎模型在建築上尚未穩定勝過統計基準 [A8]。

**本專題的新提案：** 把「可重現的數值異常」轉成「有證據、可回查、不超出資料能力的調查建議」。

- **數值層：** B0／B1 基準、校準門檻與事件合併全部由 Python 完成。
- **規劃層：** LLM 在白名單與預算內，選擇前提成立的領域規則。
- **證據層：** 每個主張都綁定 evidence_id，驗證失敗即降級為模板。
- **評估層：** 以固定報表、固定流程＋LLM、受限 Agent 三組比較，分離 Agent 的額外價值。

這是本專題選定的實作與驗證問題，**不宣稱**所有文獻都沒處理過這個組合，也不主張演算法首創。

## O. Organize：方法優缺點比較表

| 方法類別 | 代表文獻 | 優點（S） | 缺點（W） | 機會（O） | 威脅（T） | 本專題採用方式 |
|---|---|---|---|---|---|---|
| 統計／M&V 基準 | [D8][D11] | 可重現、成本低、可解釋 | 無法辨識根因；受營運變動影響 | 適合作為數值核心 | 被誤讀為節電量 | **採用**（B0／B1） |

| LLM 直接判讀／解釋 | [A5][A6] | 自然語言說明 | 數值不可靠、說明不等於因果 | 多模態輸入 | 幻覺主張 | **不讓 LLM 產生數值** |
| LLM 生成規則／程式 | [A2][A4] | 可檢查中介、可重現 | 需要標註或語意模型；仍有錯誤 | 規則可審查 | 規則錯誤擴散 | 改用**人工定義**的條件式規則 |
| 工具型 Agent（能源） | [A1][A7][A10] | 依觀察調整步驟 | 正確率不穩；部署證據少 | 工作流程層 | 迴圈、越權工具 | **受限規劃＋預算＋證據驗證** |

## 收斂：Existing Research → Limitations → Research Gap → Our Project

| 階段 | 內容 |
|---|---|
| **Existing Research** | 統計／M&V 基準已能可靠建模 [D11]；公開資料集與標註基準可以重現 [D3][D10]；LLM Agent 已能查詢建築資料並使用工具 [A1][A4][A7]；LLM 可以產生規則或說明 [A2][A5] |
| **Limitations** | 總表無法驗證個別措施或設備 [D8]；清理可能刪除異常 [D6]；LLM 直接判讀數值不可靠 [A6]；能源 Agent 正確率不穩 [A7]、部署證據極少 [A10]；TSFM 尚未穩定勝過統計基準 [A8]；監督方法需要總表所沒有的故障標籤 [A9][D13] |
| **Research Gap** | 對**只有建築總表與天氣、沒有故障標籤**的情境，缺少一個「數值可重現、主張可回查、能明確拒絕過度推論」的調查流程，也缺少能分離 Agent 額外價值的公平評估（這是本專題選定的驗證問題，不宣稱文獻完全空白） |
| **Our Project** | Energy Detective：Python 負責數值，受限 LLM 負責規劃與條件式規則選擇，報告以證據契約加上模板降級；以 B0／B1、合成擾動與三組 × 10 案例 × 3 次的協議驗證（`openspec/specs/offline-evaluation`） |
